时程簿 · 项目介绍与技术详解

一个移动端优先的 PWA 个人全天时程管理应用。这篇文档帮你把这个项目「看懂、讲清」，面试被问到能对答如流。

一句话介绍：时程簿把「课表、睡眠、安排、计划」都填进 24 小时时间轴，空闲时间自动算出，打开就能看到今天每一刻在干嘛。

技术关键词： ViteReactTypeScriptPWAIndexedDB腾讯云 CloudBaseOpen-Meteo

一、这个软件解决什么问题

很多人用课表 App 只关心「几节课」，但时程簿想管的是「一个人一整天的每一刻」：几点上课、几点睡觉、空闲时间在哪、计划安排放哪。

24小时 = 课程 + 睡眠 + 安排 + 计划 + 空闲

你只需要维护「课 / 睡 / 安排 / 计划」这四类输入，App 自动把一天铺满，剩下的自然就是「空闲」——改任何一项，全天的图立刻重算。

二、整体架构（先看这张图，再逐个拆）

浏览器（手机/电脑）→React 界面→数据层→本地 IndexedDB / 云端 CloudBase

架构上分三层，理解这三层就够了：

  • 界面层：React 组件，负责画「今天/周/月」三个视图、时间轴、表单。
  • 逻辑层：TypeScript 函数，负责算单双周、算空闲、算统计。
  • 数据层：未登录存本地（IndexedDB），登录后存云端（CloudBase 数据库）。

三、前端框架：Vite + React + TypeScript

3.1 这三个是什么

名字它是什么（大白话）为什么用它
Vite一个「开发+打包」工具，把你写的代码打包成浏览器能跑的最终文件启动快、配置简单，是现在前端最主流的选择
React一个「画界面」的框架，把界面拆成一个个小组件（组件 = 函数）组件化好维护，生态最大，面试必问
TypeScript带「类型」的 JavaScript，给数据规定好形状，写错会提前报错防止低级 bug，写大项目更稳
面试金句：我用 TypeScript 定义好了所有数据模型（课程、事件、计划），这样在写代码时就能提前发现「字段写错、类型不匹配」的问题，项目跑起来更稳。

3.2 一个 React 组件长什么样（本项目真实例子）

// src/components/NowCard.tsx ——「现在」卡片
export function NowCard({ blocks }: { blocks: Block[] }) {
  const { now, current, next } = nowInfo(blocks)   // 算出现在在干嘛、下一件
  return (
    <div className="nowcard">
      <div>{toHHMM(now)}</div>
      {current ? <div>{current.title}</div> : <div>现在是空闲时间</div>}
      {next && <div>下一件 · {next.title}</div>}
    </div>
  )
}

看懂关键点：组件就是一个函数，输入数据（props），输出界面（JSX）。React 会在数据变化时自动重新渲染界面。

四、界面怎么做的：纯 CSS + 设计变量 + SVG 图标

  • 没用什么 UI 组件库（比如 Ant Design、Element），而是自己用「纯 CSS」写，这样体积小、可控性强。
  • 设计变量（CSS Variables）：把颜色统一定义成变量，比如 --accent: #2E7D6B。这样「主题色自定义、深色模式」只要改几个变量，全站就换色。
  • 图标用 Lucide：开源的线性 SVG 图标库，风格统一、可换颜色。
  • 刻意不用渐变色（避免「AI 味」），走极简工具风。
面试金句：我用 CSS 变量做了「主题色 + 深色模式」的可定制设计，颜色改动只影响几个变量，不散落在代码各处。

五、数据层：本地 + 云端「双模式」（这是项目最有意思的地方）

数据有两种存法，App 会自动切换：

模式存哪特点技术
未登录（本地）浏览器 IndexedDB无需账号，但换设备/清缓存就没了Dexie（IndexedDB 的封装）
已登录（云端）腾讯云 CloudBase 文档数据库跨设备同步、不丢失、按账号隔离CloudBase JS SDK

5.1 关键设计：两个数据层的「接口一样」

// 本地：useAppData()  ←→  云端：useCloudData()
// 两者返回一模一样的接口：{ courses, events, saveCourse, deleteCourse, ... }
// App 里一行切换：
const store = authUser ? cloudStore : localStore

这就是「接口抽象」：上层界面不关心数据存在哪，只要两个实现提供同样的方法即可。这是面试很加分的点。

六、核心业务逻辑（这部分面试最爱问「你实现了什么算法」）

6.1 单双周怎么算

// 学期开始日期（周一）→ 算出今天在第几周 → 周数奇偶 = 单双周
weekNumber = 从学期开始到今天过了几天 ÷ 7 取整 + 1
单周 = 周数 % 2 === 1，双周 = 周数 % 2 === 0

6.2 空闲时间怎么算

// 把一天的所有「块」按开始时间排序，块与块之间的空隙 = 空闲
freeSlots = 遍历排序后的块，累计「上一块的结束 到 下一块的开始」

6.3 计划自动推荐

用户说「每周跑步 3 次」→ 在接下来 7 天里，找出时长 ≥ 30 分钟的空闲时段 → 推荐给用户勾选。

七、登录与认证

登录用 腾讯云 CloudBase 认证，采用「用户名 + 密码」登录。注意：因为用的是免费体验版，短信/邮箱验证码开不了、用户名密码又不支持自助注册，所以账号由管理员在控制台创建，用户直接登录。

八、PWA：为什么能「添加到主屏幕」

PWA（渐进式 Web 应用）= 网页 + manifest.json（声明图标、名称）+ Service Worker（缓存文件，实现离线）。用户打开网址后点「添加到主屏幕」，就像装了个 App。

  • 本项目的 PWA 由 vite-plugin-pwa 自动生成。
  • 图标是用 Node 脚本程序化画出来的（时钟图标 PNG，做了 3 倍超采样抗锯齿）。

九、天气功能

现在卡右上角显示当前温度 + 天气图标。实现：浏览器定位（或手动城市）→ 调 Open-Meteo 免费天气接口 → 根据天气代码显示对应 SVG 图标。

十、怎么部署上线的

写代码→npm run build（打包）→tcb hosting deploy（上传）→CloudBase 静态托管（拿 https 网址）
  • 打包产物在 dist/ 目录。
  • 用 CloudBase 命令行工具 tcb 上传到「静态网站托管」。
  • 最终得到 https://xxx.tcloudbaseapp.com 的正式网址。

十一、面试怎么讲（30 秒版 + 详细版）

30 秒版：我做了一个移动端优先的日程管理 PWA「时程簿」，用 React + TypeScript 开发，把课表（含单双周）、睡眠、安排、计划统一到 24 小时时间轴，空闲时间自动计算；数据层做了「本地 IndexedDB + 云端腾讯云 CloudBase」双模式，支持登录后跨设备同步；已部署上线。

可能被追问的问题：

  • 「单双周怎么实现？」→ 按学期开始日期算周数，奇偶判断。
  • 「数据存哪？」→ 未登录本地 IndexedDB，登录后云端文档数据库，按用户 uid 隔离。
  • 「为什么本地云端双模式？」→ 降低使用门槛（不登录也能用）+ 多端同步（登录后数据上云）。
  • 「怎么部署的？」→ CloudBase 静态托管 + CLI 上传 dist。
  • 「遇到什么难点？」→ 见《开发流程与经验总结》文档里的踩坑记录。
