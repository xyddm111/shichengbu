时程簿 · 开发流程与经验总结

从「一个想法」到「上线的软件」，完整记录了开发流程、每一步做了什么、以及踩过的坑和学到的经验。

一、完整开发流程（7 个阶段）

1
需求梳理：先不写代码，和用户反复讨论「到底要做什么」。
确定了：核心是「人的一天每一刻」——课表(单双周)、睡眠、安排、计划、空闲自动算；视图有「现在/今天/周/月」；还要登录、多用户、部署上线。
经验：需求没聊清楚就写代码，等于返工。这一步花了最多时间，但最值。
2
设计与选型：确定「网页 PWA（而非原生 App）」+「极简工具感设计」+「先本地、后云端」。
设计上明确：不用渐变色、图标用 SVG、时程表放首页打开即见、底部五 Tab 导航。
3
搭骨架：创建 Vite + React + TypeScript 项目，写设计变量、基础组件、数据层。
顺序：设计变量 → 基础组件 → 数据层 → 视图 → 表单。
4
开发核心功能：今天/周/月视图、时间轴、课表录入(单双周)、计划推荐、统计等。
每做一个功能就跑 npm run typecheck（类型检查）+ npm run build（构建）验证。
5
自我审查 + 迭代：类型检查 0 错误、构建成功、冒烟测试；再根据用户反馈一轮轮打磨界面（导航、时间轴、颜色、图标…）。
经验：把东西先跑起来给用户看，再根据反馈改，比闭门造车高效得多。
6
接云端 + 登录：注册腾讯云 CloudBase，接入登录认证、云数据库（按账号隔离）、数据上云。
7
部署上线：打包 dist/，用 CLI 上传到 CloudBase 静态托管，拿到正式 https 网址，手机可「添加到主屏幕」。

二、每一步的关键经验

阶段关键经验
需求多问、多确认；把「要做什么」和「不做什么」都写清楚
设计先定「设计变量/配色/组件」，再动手，避免风格打架
数据层定义好数据模型（types），本地和云端接口保持一致，方便切换
开发每个小功能都做类型检查 + 构建，别攒到最后
测试真机测试（手机浏览器），因为手机和电脑表现不同
部署上线后 CDN 有缓存，改版要强刷

三、踩过的坑（重点，面试也可能问「遇到过什么困难」）

坑 1：npm 安装依赖被沙箱拦 —— 全局缓存目录不在可写范围，报 EPERM。
解决：把缓存重定向到项目内 --cache .npm-cache，并用 --ignore-scripts 跳过需要派生进程的脚本。
坑 2：构建时 esbuild 派生子进程报 EPERM —— 沙箱禁止「管道捕获子进程输出」。
解决：在更高权限模式下运行构建命令。
坑 3：CloudBase 大改版 —— 一开始按老文档的「按量计费免费额度」走，结果发现现在是「套餐制」（免费体验版/个人版），数据库也分「PostgreSQL(默认)」和「云数据库(文档型)」。
解决：及时查官方最新文档，确认本项目用「云数据库」。
坑 4：免费体验版不能自助注册 —— 短信/邮箱验证码是灰色开不了；「用户名密码」又只支持登录不支持注册（注册接口直接返回 501）。
解决：改成「管理员创建账号 + 用户名密码登录」。
坑 5：SDK v1/v2 接口混乱 —— 新版 SDK 的 signUp 要求邮箱/手机，而用户名密码登录要用旧版兼容方法 signInWithUsernameAndPassword。
解决：读 SDK 的类型定义文件（.d.ts）确认到底有哪些方法，而不是猜。
坑 6：云数据库集合不会自动创建 —— 直接写入报错/卡住。
解决：用 CLI 的 INSERT 触发创建集合（已建好 5 个：semester/courses/sleep/events/plans）。
坑 7：命令行传 JSON 被 PowerShell 转义搞坏 —— 嵌套引号被吃掉。
解决：改用 Node 脚本 JSON.stringify 构造参数再调用 CLI，绕开 shell 转义。
坑 8：PWA/CDN 缓存导致「刷新没反应」 —— 部署新版本后，浏览器/CDN 还缓存着旧版。
解决：提醒用户「强刷」或等几分钟 CDN 刷新。

四、方法论总结（几条通用心法）

  • 先设计后编码：需求、数据模型、配色、组件都想清楚再动手，能省大量返工。
  • 小步快跑 + 频繁验证：每做一点就类型检查/构建/给用户看，别攒大问题。
  • 接口抽象：本地/云端数据层做成同一套接口，上层无感切换，这是本项目最值得说的设计。
  • 读源码/类型定义：SDK 文档过时或不清晰时，直接读它的 .d.ts 类型定义最靠谱。
  • 遇到外部平台改版，先查官方最新文档，别死磕旧教程。
  • 把过程和坑记录下来（就像这份文档），下次能无缝继续。

如果面试问「这个项目你学到了什么」，可以这样答：

「我完整走了一遍从需求、设计、开发到部署上线的流程，学会了两件最重要的事：一是用 TypeScript 和接口抽象让数据层能本地/云端双模式无缝切换；二是遇到第三方平台（CloudBase）改版、沙箱限制等意外时，学会查官方文档、读 SDK 类型定义来定位问题，而不是瞎试。」
