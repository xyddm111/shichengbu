时程簿 · 注册功能优化方向

现状是「不能自助注册、只能管理员建账号」。这篇讲清楚为什么会这样，以及以后想支持自助注册有哪些方向、各要多少成本。

一、现状：为什么现在不能自助注册

根本原因是用了 CloudBase 免费体验版，它有两个限制：

  • 短信验证码、邮箱验证码开不了（控制台里是灰色，因为免费版不提供发短信/发邮件的服务）。
  • 「用户名密码」登录方式只支持登录、不支持注册（实测注册接口直接返回 501「不支持」）。

所以现在只能：管理员（你）在控制台「用户管理」里手动创建账号，朋友拿你给的「用户名 + 密码」登录。

二、优化方向对比（4 条路）

方向怎么做成本难度推荐度
A. 升级套餐开邮箱 CloudBase 升级到「个人版」（19.9元/月）→ 开启「邮箱验证码」→ 用户用邮箱+验证码自助注册 每月 19.9 元 低（改少量代码） ⭐⭐⭐⭐⭐ 最推荐
B. 邀请码 + 邮箱自助注册 在 A 的基础上，注册时校验邀请码，控制谁能进（原计划的方案） 同 A 低 ⭐⭐⭐⭐ 配合 A 用
C. 微信登录 CloudBase 支持微信登录，但需要「微信开放平台」账号 + AppID（要企业/个人开发者资质、审核） 要资质+审核 中 ⭐⭐ 小范围用不划算
D. 自建后端账号系统 用 CloudBase 云函数 + 云数据库自己写「注册/登录/密码加密」，完全可控 云函数免费额度 高（要写后端逻辑） ⭐⭐ 学习价值大，工程量大

三、各方向的详细说明

方向 A：升级套餐开邮箱（最省事）推荐

把 CloudBase 套餐从「免费体验版」升级到「个人版」（19.9 元/月），就能开启「邮箱验证码」。然后：

  • 注册流程变成：用户填邮箱 → 收到验证码 → 输入验证码 → 自动注册并登录。
  • 代码改动很小：把现在的「管理员建账号」换成邮箱验证码登录即可（SDK 已有 getVerification + signInWithEmail 方法）。

方向 B：加邀请码（配合 A）

这是当初最想要的方案：自助注册，但要输入邀请码，只有拿到你邀请码的朋友才能注册，实现「小范围私密使用」。实现：注册前读一个公开的「config」集合里的邀请码做校验即可（代码里已经有这个接口的雏形）。

方向 C：微信登录

适合想「一键微信登录」的场景，但个人开发者申请微信开放平台 AppID 有门槛（要审核、可能要企业资质），小范围朋友使用不划算。

方向 D：自建后端账号系统

如果你以后想练后端，这是最好的学习方向：用 CloudBase 云函数 + 云数据库自己写一套「注册、登录、密码加盐哈希、Token 签发」。完全可控、不依赖平台认证，但工程量大、要考虑安全问题（密码不能明文存）。

四、结论

建议路线：先维持现状（管理员建账号，免费）；等真的需要「朋友自助注册」了，就 升级个人版（19.9/月）→ 开邮箱验证码 → 加邀请码校验，一步到位实现当初设计的「邀请码 + 邮箱自助注册」。

如果你只是想「给自己和几个朋友用」，现在这个「管理员建账号」的方式其实已经够用，而且免费。
